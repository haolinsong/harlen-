# 当前项目工作原理

## 一句话结论

这个项目是 Harlan 的技术第二大脑：Harlan 负责投递资料、提出问题和验收方向，Agent 负责把资料读懂、提炼、交叉链接、归档到 wiki，并把有价值的回答写成 outputs 里的复习材料。

## 三层结构

项目按 Raw / Wiki / Outputs 三层运行。

`raw/` 是事实来源层，归 Harlan 拥有，Agent 默认只读。外部文章、官方文档、PDF、报错记录放在这里；个人排障和学习记录放在 `raw/personal/`，因为个人判断不能给自己的结论反复背书。

`wiki/` 是知识网络层，归 Agent 维护。它不是简单存摘要，而是把来源编译成可长期维护的页面：来源页记录材料讲了什么，概念页回答“是什么、为什么”，howto 页回答“怎么做”，实体页记录工具、框架、人物等对象，`overview.md` 负责全局判断，`index.md` 负责导航入口，`log.md` 负责时间线。

`outputs/` 是复习与结论层，给 Harlan 读。它不承担 wiki 导航任务，而是把问答、审计、复习卡写成独立可读的成品。重要结论不能只留在对话里，必须落盘到这一层。

## 核心工作流

日常循环是：投递来源 -> 摄入 -> 更新 wiki -> 提问 -> 结论落盘 -> 体检 -> 继续投递。

摄入时，Agent 先读来源，提炼要点，再检查已有页面和 aliases，避免同一个概念长出多个名字。确认归属后，Agent 写或更新来源页、概念页、实体页；如果资料里有可复用步骤，还要写 howto 页并给出验证方式。最后更新 `wiki/index.md` 和 `wiki/log.md`。

提问时，Agent 不直接翻 raw 全文，而是先读 `wiki/index.md` 定位相关页面，再深入 wiki 作答。这样回答依赖的是持久化知识网络，而不是当前会话的短期上下文。只要答案有复习价值，就先对齐已有输出主题：命中则更新主题原页，没有对应主题才新建，并在 index 登记。

体检时，先跑 `python3 scripts/lint.py` 检查 frontmatter、断链、孤立页、index 一致性、别名冲突、来源覆盖率和时效；再补脚本看不出的语义问题，例如结论冲突、页面粒度漂移、缺失交叉引用。

## 当前状态

截至 2026-09-24，库的三层结构已经成型，已有 3 份方法论来源、3 个知识管理概念、2 个实体和 5 篇主题输出页。Java 消息队列方向已经形成选型总览、RabbitMQ 入门实战和 Maven Wrapper 三个稳定学习入口，并配有可运行的 Spring Boot 项目；wiki 中的技术概念页和 howto 页仍有较大扩充空间。

输出层已经从“每次问答生成一份日期快照”改为“一个学习主题对应一篇持续更新的活文档”。下一步最有价值的动作是继续投递真实技术来源，并在提问时优先补厚已有主题，让 wiki 的知识网络和 outputs 的学习路径同步成长。
