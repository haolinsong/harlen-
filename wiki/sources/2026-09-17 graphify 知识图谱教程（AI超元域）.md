# graphify 知识图谱教程（AI超元域）

**一句话摘要**：一期视频转录稿，介绍开源工具 **graphify**——把 Karpathy 的「raw → wiki」工作流**产品化并图谱化**：它把任意语料（代码、文档、论文、图片）编译成持久化、可查询、带审计轨迹的知识图谱，并以 skill 形式挂载到 Claude Code / Codex / OpenCode / OpenClaw 上，可导出到 Obsidian。

## 核心内容

### 1. 定位

graphify 自称"AI 编程助手的 skill"，可以理解为对 Karpathy 知识库工作流的**工程化 + 图谱化**实现：同样是 raw 文件夹进、结构化知识出，但产出物从 markdown wiki 变成知识图谱。

### 2. 五层架构（视频口述）

| 层 | 组件 | 要点 |
| --- | --- | --- |
| 输入层 | 文件检测、URL 摄入、语义缓存 | 自动分类 13 种代码/文档/论文/图像，递归扫描目录 |
| 核心处理层 | **AST 结构提取** | 对代码做确定性解析，**不调用大模型、不消耗 token** |
| | **语义提取** | 用并行子代理从文档/论文/图片中抽取实体与关系 |
| | 图谱构建 | 合并 AST 与语义两条通道的结果 |
| 分析层 | 社区发现、结构分析、token 基准测试 | 自动发现主题簇 |
| 输出层 | 审计报告、多格式导出、wiki 生成 | 可导出 Obsidian 库 |

另有基础设施层（视频未展开）。

### 3. 相对 Karpathy 流程的三点变化

视频称之为"三个飞跃"：

1. **扁平 wiki → 关系图谱**：知识以节点与边组织，而非一堆独立页面。
2. **LLM 索引 → AST + 语义双通道**：代码用确定性解析，只有不可结构化的内容才交给 LLM。
3. **人工维护 → 算法发现**：社区发现等算法自动识别结构，取代人工分类。

### 4. 为什么值得挂到编程助手上

- Claude Code 自带的记忆是**线性、文件驱动**的；图谱相当于在其上叠加一层**结构化认知层**。
- 检索方式从 grep / 逐文件搜索，变成**沿图谱导航**。
- 视频声称能大幅**节省 token**、快速上手陌生代码库、发现隐藏耦合。
- 支持**跨模态混合语料**：把代码、设计文档、相关论文放进同一张图。
- workspace 变更后图谱可**增量更新**（`update`）。

### 5. 实测演示（视频中以 memorydb 项目为例）

| 命令 | 演示的动作 | 结果 |
| --- | --- | --- |
| `/graphify .` | 从项目根目录全量构建图谱 | 生成图谱文件，浏览器可视化 |
| `query` | 问"BM25 的代码在哪个文件" | 给出两个文件路径 + **代码行号** |
| `explain` | 解释"智能提取"如何实现 | 输出流程图 + 设计决策（六种记忆、两阶段去重） |
| `query` | 查 Gemini embedding 模型维度 | 答 3072 维，并附代码位置 |
| `update` | 合并一个 PR 后更新图谱 | 图谱反映改动，`explain` 能解释修复逻辑 |
| `add <论文链接>` | 把一篇记忆相关 arXiv 论文加进图谱 | 论文的 5 个因子与项目实现逐项对应 |
| `path` | 追踪论文节点与代码实现之间的图谱路径 | 输出路径图与关联分析 |
| 导出 | 生成 Obsidian 库 | 可在 Obsidian 中浏览管理 |

安装方式：直接执行仓库给出的命令，或把仓库链接丢给 Claude Code / Codex，让它自己安装并配置。
