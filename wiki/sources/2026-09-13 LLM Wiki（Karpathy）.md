# LLM Wiki（Karpathy）

**一句话摘要**：一份写给 LLM Agent 的"构想文件"（idea file），主张用 LLM 增量维护一个持久 wiki 来取代"查询时检索"的 RAG 模式。它刻意不提供实现——具体结构由你与 Agent 共同长出来。

## 出处

- 原文：<https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f>
- 作者：Andrej Karpathy
- 本地副本：`raw/llm-wiki.md`（Obsidian Web Clipper 抓取于 2026-09-13，2026-09-17 从 `raw/assets/` 移至 `raw/`）
- 体裁：抽象的模式说明，非规范、非代码、非软件项目

## 核心论点

1. **RAG 的缺陷是不积累**：每次提问都从原始片段重新拼装，跨文档综合的成本被反复支付，没有任何东西被沉淀下来。
2. **把编译时机从查询时挪到摄入时**：新来源不只是被索引，而是被读进来、提炼，并**合并进已有的知识网络**——更新实体页、改写主题总结、标注新旧矛盾。
3. **wiki 是复利资产**：交叉引用已经写好，冲突已经标记，综述已经反映读过的全部内容。
4. **分工明确**：人类负责选材、探索、提出好问题；LLM 负责摘要、交叉引用、归档、记账。
5. **真正的瓶颈是记账**（bookkeeping），不是阅读或思考。人类会因为维护成本增长快于价值而放弃 wiki，LLM 不会。

## 三层架构

| 层 | 内容 | 归属 | 性质 |
| --- | --- | --- | --- |
| Raw sources | 文章、论文、图片、数据文件 | 人类 | 不可变，事实来源 |
| The wiki | 摘要、实体页、概念页、对比、综述 | LLM | LLM 全权撰写 |
| The schema | 如 `CLAUDE.md` / `AGENTS.md` | 共同演进 | 规定结构与工作流 |

## 三个操作

- **Ingest**：把来源丢进 raw，并**告诉 LLM 处理它**。流程为：读来源 → 与你讨论要点 → 写摘要页 → 更新 index → 更新受影响的实体与概念页 → 追加 log。单份来源可能触及 10–15 个页面。
- **Query**：对着 wiki 提问，带引用作答。**好答案要回流成新页面**，让探索也复利。
- **Lint**：定期体检——页面间矛盾、被新来源推翻的过期结论、无入链的孤立页、被反复提及却没有独立页面的概念、缺失的交叉引用、可用外部检索填补的空白。

## 两个特殊文件

- `index.md`：**内容导向**的目录，每次 ingest 后更新。回答问题时先读 index 再深入——约 100 个来源以内够用，无需向量检索基础设施。
- `log.md`：**时间导向、只追加**。统一的前缀格式（如 `## [2026-04-02] ingest | 标题`）使其可被 `grep "^## \[" log.md | tail -5` 解析。

## 可选组件与技巧

- 搜索工具（如 [qmd](https://github.com/tobi/qmd)）等规模变大后再引入，小规模时 index 文件就够。
- **Obsidian Web Clipper** 负责把网页文章转成 markdown 来源。
- 附件目录固定到 `raw/assets/` 后，可用「Download attachments for current file」把图片下载到本地，让 LLM 能直接看图。
- 图谱视图看结构；Marp 生成幻灯片；Dataview 基于 frontmatter 生成动态列表；整库作为 git 仓库获得版本历史。

## 思想脉络

作者自陈与 Vannevar Bush 1945 年的 **Memex** 同源：私人、主动策展，文档之间的关联与文档本身同样有价值。Bush 当年唯一没能解决的是"谁来做维护"。

> [!info] 分析（非原文观点）
> 这份文档的价值不在"个人 wiki"这个概念——它早已存在——而在于两个判断：一是**维护而非采集才是知识库的真正瓶颈**；二是维护恰好是 LLM 擅长的劳动（琐碎、重复、对一致性敏感、大批量小改动）。由此个人知识库的经济学模型被翻转。

> [!question] 待验证
> 作者声称 index 文件在"约 100 个来源、数百个页面"规模内足以导航。这个上限对中文内容、对结构松散的主题是否同样成立？需要在积累过程中实测。

## 局限（本页分析，非原文观点）

- **验证负担转移给人类**：wiki 内容全部由 LLM 撰写，错误会静默累积，人类是唯一的质量闸门。
- **写入放大**：一份来源牵动 10–15 个页面，改得越多越容易不一致，diff 也越吵。
- **冲突处理是政策而非机制**：schema 里的"不要静默覆盖"没有强制力。
- **不可复现**：同一来源摄入两次会得到两个不同的 wiki。
- **不解决来源获取**：输入端仍然靠人类在外面读到、筛选、投递。

## 与本站的关系

本库（`Harlan的第二大脑`）正是这份文档的一个实例化：三层结构、以 `AGENTS.md` 作为 schema、`index.md` 与 `log.md` 两个特殊文件均已落地，只砍掉了可选工具层。因此这份来源带有**元文档**性质——它既是知识，也是本库的出生证明。
