# 持久 Wiki 模式

**定义**：用 LLM 增量维护、持续变厚的个人知识库模式——在原始资料与提问者之间放一层由 LLM 全权撰写的 markdown wiki，知识在**摄入时**被编译并保持最新，而不是在**查询时**被重新推导。

## 与 RAG 的本质差别

| | RAG / NotebookLM | 持久 Wiki |
| --- | --- | --- |
| 知识形态 | 原始片段，查询时拼装 | 已编译的中间层 |
| 跨文档综合 | 每次重新做 | 已经写在那里 |
| 矛盾 | 通常不会被发现 | 在摄入时即被标记 |
| 成本曲线 | 每次提问付一遍 | 摄入付一次，之后递减 |
| 撰写者 | 人类（或没人） | LLM |
| 人类角色 | 提问者 | 选材者 + 提问者 + 验收者 |

## 为什么有效

维护（记账）的成本对 LLM 接近于零。人类放弃知识库的原因是维护负担的增长速度超过价值的增长速度，而 LLM 不会无聊、不会忘记更新一处交叉引用、一次能改 15 个文件。个人 wiki 的经济学因此被翻转。

人类那部分工作不缩水，且不可替代：**策展来源、决定分析方向、提出好问题、判断意义**。

## 成立的四个必要条件

1. **一个 schema 文件**（`AGENTS.md`）——会话没有记忆，这是约定唯一能跨会话传递的载体。
2. **一个内容索引**（`index.md`）——Agent 先读目录再深入，替代向量检索。
3. **一条时间线**（`log.md`）——让 Agent 知道最近发生了什么，兼作审计记录。
4. **冲突必须显式标注**——否则最早的结论会静默固化，wiki 随时间腐烂。

常见但可选：来源带 frontmatter（供 Dataview 查询）、附件本地化（让 LLM 能看图）、整库纳入 git（获得 diff 与回滚能力）。

## 适用与不适用

**适用**：单人、长期、围绕稳定主题的积累——研究方向深耕、伴读一本书、个人成长与健康记录、竞品或尽调情报库。

**不适用**：一次性问答；上万文档的企业语料；多人实时协作；以及任何**正确性不容出错**的场景（法律、医疗决策），除非有人类逐条核对。

## 已知失效模式

- 错误静默累积，缺乏自动校验，人类是唯一闸门
- 写入放大导致页面之间逐渐漂移
- 索引检索在规模变大后失效，需要引入真正的搜索
- 摄入过程不可复现
- "不要静默覆盖"依赖 Agent 自律，没有强制力

## 图谱化演进（2026-09-17 补充）

第二份来源 [[2026-09-17 graphify 知识图谱教程（AI超元域）]] 提出了这条路线的一个变体：不写 markdown wiki，而是把 raw **编译成知识图谱**（见 [[知识图谱编译]]）。它带来的三点变化是——扁平页面变关系图谱、LLM 索引变 AST 与语义双通道、人工维护变算法发现。

> [!warning] 冲突
> **本模式主张"LLM 撰写并维护 wiki"是核心；图谱路线主张"能用算法的不用 LLM"（代码走 AST，零 token）。**
> 两者对"维护成本来自哪里"的判断不同：前者认为成本在跨页面的记账劳动，交给 LLM 最划算；后者认为相当一部分结构本来有确定答案，交给算法更便宜也更准。
> 目前的判断是**两者互补而非替代**——图谱擅长定位与关系，wiki 擅长综合与叙事，冲突只发生在"代码类语料"这一局部。此结论等待第三份来源检验。

这条路线同时回应了本页"已知失效模式"里的第一条：AST 通道是确定性的，不产生幻觉，因此那部分知识不存在"错误静默累积"的问题。

## 外部验证与运维实践（2026-09-17 补充）

第三份来源 [[2026-09-17 LLM Wiki 搭建教程（飞书云文档）]] 提供了**外部验证**：这套模式已经被社区教程化，有人在 2026 年 4 月就照它搭过库，并留下了完整的问题清单。这说明本库走的不是一条无人走过的路，代价与坑都有人先趟过。

该来源也给出了一条对"已知失效模式"的**现场证据**：有用户报告"摄入当天提问很准确，第二天同样的问题就索引不到，重新摄入后又正常"——这几乎确定是**把会话上下文误当成了持久检索**。它印证了本页第 2 条必要条件（`index.md`）不是可选项：没有"每次新会话先读 index"这个强制动作，wiki 就等于不存在。

具体可复用的配置与故障清单，已单独提炼到 [[持久 Wiki 实践要点]]。

## 工程化扩展（2026-09-17 补充）

同一来源的**完整正文**（现已重建入库，见 [[2026-09-17 LLM Wiki 搭建教程（飞书云文档）]]）给出了一套工程化程度更高的实现。相对本模式的三操作，它有三点结构性变化：

1. **第三层从 Schema 变成 Outputs**——把"答案必须持久化"从一句约定升级为架构的一层（`wiki/outputs/`）。本模式只说"好答案可以归档"，它规定必须落盘。
2. **操作从三个扩展到六个**——新增 REFLECT（二阶合成）、ADD-QUESTION（开放问题队列）、MERGE（去重合并）。其中 REFLECT 是唯一一个**主动产出新知识**而非整理已有材料的操作。
3. **加了一整套护栏**——来源哈希校验、置信度分级（high 必须人工确认）、时效衰减、图谱隔离。

> [!info] 它正面回应了本模式的第五条失效模式
> 本页"已知失效模式"里写着"错误静默累积，缺乏自动校验，人类是唯一闸门"。这套实现用七道防线补上：哈希防源文件被改、aliases 双查防重复建页、Evolution Log 防过程丢失、置信度防自动晋升、时效阈值防陈旧固化、**个人写作不计 source_count 防自证**、graph-excluded 防图谱污染。
> 其中"个人写作不参与置信度计数"最锋利：它明确阻止"用自己的文章给自己的观点背书"——而这恰恰是个人知识库最常见的自欺形式。

> [!warning] 回音室风险
> REFLECT 的 Stage 0 规定：生成任何合成结论之前，先主动搜索反驳证据；**找不到反对来源时，必须标注「⚠ 回音室风险：未找到反驳来源，结论可能存在确认偏差」**。
> 这一条与本库的处境直接相关：`overview.md` 已记录本库三份来源**全部是同一主题、全部是二手材料**。按这条规则，本库目前产出的任何"结论"都应该带上回音室风险标注。

## 思想脉络

与 Vannevar Bush 的 Memex（1945）同源：私人、主动策展，把文档之间的关联视为与文档本身同等重要。也与卢曼卡片盒笔记法（Zettelkasten）精神相通——区别在于链接与索引的维护者从人换成了 Agent，瓶颈因此转移到人类的选材速度上。
