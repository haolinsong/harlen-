# 持久 Wiki 实践要点

**定义**：搭建与长期维护一个持久 Wiki 时反复出现的工程细节、可复用的配置，以及社区已经踩过的坑。这一页不讨论"为什么"（那是 [[持久 Wiki 模式]] 的职责），只记录"怎么做、哪里会出错"。

## 目录布局：两种流派

| | 扁平布局（本库采用） | 分区布局（飞书教程采用） |
| --- | --- | --- |
| 文章剪藏 | `raw/` 根下平铺 | `raw/clippings/` |
| 图片附件 | `raw/assets/` | `raw/images/` |
| 优点 | 结构最简，新增来源零心智负担 | 来源与附件天然分离，附件多时更清爽 |
| 代价 | 附件与文章混在同一棵树下（本库确实踩过：剪藏误存进 `raw/assets/`） | 多一层目录，路径更长 |

社区共识是 **`raw/` 下的目录结构可以按需替换**，改完告诉 Agent 更新 schema 即可。布局本身没有对错，重要的是 schema 里写清楚。

## 检索工具：什么时候该升级

按规模递进，不必提前引入：

1. **`index.md` 目录导航** —— 约 100 份来源以内够用，零依赖。本库目前处于这一档。
2. **qmd** —— 本地 markdown 搜索引擎（BM25 + 向量 + LLM 重排）。仓库是 `github.com/tobi/qmd`，但 **npm 包名是 `@tobilu/qmd`**，按 `@tobi/qmd` 安装会报 404。
3. **ripgrep (`rg`)** —— qmd 装不上时的替代（如 Windows 无 WSL 的环境）。能力弱一些，但 200 多篇 md 的规模够用。

未解决的已知问题：有人报告 qmd query 会卡在 "gathering information"，原因不明。

## Obsidian Web Clipper 配置要点

- **文章保存路径**与**附件路径**是两个独立设置。本库曾因两者共用而把剪藏存进了 `raw/assets/`。
- 模板变量里 **`date` 不能写成 `data`**，否则报 `Unknown variable "data"`。正确写法：`{{date|date:YYYY-MM-DD}}-{{title}}`。
- 建议绑定快捷键下载附件，把图片存到本地而不是留外链。

## 已知故障清单

| 现象 | 最可能的原因 | 状态 |
| --- | --- | --- |
| 摄入当天提问很准，**第二天就索引不到**，重新摄入又正常 | **会话上下文被误当成持久检索**：准确回答靠的是当前对话，而非真的读了 wiki | 有解，见下 |
| qmd query 卡在 gathering information | 不明（Windows 环境下多人遇到） | 未解 |
| 如何让 wiki 像 RAG 一样供外部智能体（如豆包）使用 | 需要一层检索接口 | 未解 |
| 剪藏报变量错误 | Clipper 模板变量拼写 | 有解，见上 |

**第一条的解药**：每次新会话，**必须先从读 `index.md` 开始**。这是让 wiki 真正生效的开关——没有这个强制动作，模型会假装自己知道。本库把它写进了 `AGENTS.md` 的 Query 流程第 1 步。

## 飞书教程版的额外机制（2026-09-17 补充，可选）

同一份来源的完整正文给出了本库还没有的一整套规格。以下按"是否值得跟进"排列。

### 值得直接借鉴的三条

1. **把查询答案固定落盘**（飞书把它设成独立第三层 `outputs/`）。**已采纳（2026-09-17）**：本库把 `outputs/` 立在库根、按技术栈分类，作为独立第三层，`wiki/` 归 Agent、`outputs/` 归你复习。
2. **REFLECT（二阶合成）+ 它的 Stage 0 反向检验**：生成任何合成结论前，先主动找反驳证据；找不到就必须标注「⚠ 回音室风险」。这是本库完全没有、但最需要的一环——原因见 [[持久 Wiki 模式]]。
3. **开放问题队列**（它用 `QUESTIONS.md`）：把"我想搞清楚 X"记下来，之后摄入来源时自动检查是否已回答。**已采纳（2026-09-17）**：本库 `wiki/QUESTIONS.md`。

### 页面级护栏（按规模上线）

| 机制 | 具体规则 | 何时值得加 |
| --- | --- | --- |
| 来源哈希 | source 页记 `raw_sha256`，lint 比对，变了就标 ⚠ SOURCE MODIFIED 并重新摄入 | 开始依赖某个来源的结论时 |
| 置信度 | 1 来源→low；3+→medium；5+ 且无重大矛盾→候选 high，**必须人工确认** | 概念页超过一屏时 |
| 时效衰减 | `domain_volatility` high/medium/low → stale 阈值 90/180/365 天 | 领域知识更新快时 |
| 命名规范 | 文件名用英文小写连字符 slug，中文名进 `aliases`；wikilink 只用英文 slug | **与本库现状冲突**，见下 |
| 图谱隔离 | 系统文件加 `graph-excluded: true`，不参与 Obsidian 图谱 | 图谱里开始出现系统文件时 |

### 与本库的直接冲突：页面命名

本库用中文文件名，wikilink 形如 `[[持久 Wiki 模式]]`；飞书教程版强制英文 slug + `aliases`，并明文禁止中文 wikilink。

两者都能工作，但**混用会出问题**（一半英文一半中文的链接最难维护）。目前本库的选择是保持中文，理由是库还小、读者只有一人。如果将来要接 qmd、或要按它的模板系统走，再整体迁移一次——**不要部分迁移**。

## 本库当前的选择（对照飞书教程版）

| 项 | 本库现状 | 飞书教程版 | 判断 |
| --- | --- | --- | --- |
| 布局 | `raw/`（扁平）+ `personal/` 分区 | 六个分类子目录 | 已加 personal 分区，其余保持扁平 |
| 检索 | 只用 `index.md` | index.md + qmd | 约 100 份来源后再引入 |
| lint | 已落地 `scripts/lint.py` | `scripts/lint.py` 9 项 | 已采纳 |
| 命名 | 中文文件名 | 英文 slug + `aliases` | 暂不改，但不许混用 |
| 第三层 | Outputs（顶层 `outputs/`），Schema 是配置 | Outputs | 已采纳 |
| 操作数 | 4（Ingest / Query / Lint / Add-question） | 6 | REFLECT 与 MERGE 待规模 |
| 护栏 | 时效衰减 + howto `verified` | 哈希 / 置信度 / 时效 / 隔离 | 哈希、置信度待规模上线 |
| schema | `AGENTS.md` + `README.md` | 单个 `CLAUDE.md` + `USER_GUIDE.md` | 本库的双文件分工更清楚 |
