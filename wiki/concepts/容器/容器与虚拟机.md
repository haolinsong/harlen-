# 容器与虚拟机

容器（Container）隔离的是共享宿主机内核的一组进程，虚拟机（Virtual Machine）虚拟出硬件边界并运行自己的操作系统内核。

## 核心要点

容器首先是进程，不是“缩小版虚拟机”。容器运行时利用 Linux namespaces 提供进程、网络、挂载点等视图隔离，利用 cgroups 统计和限制 CPU、内存等资源，再叠加 capabilities、seccomp、AppArmor 或 SELinux 等安全机制。

| 维度 | 容器 | 虚拟机 |
| --- | --- | --- |
| 核心对象 | 被隔离的进程 | 完整 Guest OS |
| 内核 | 多个容器共享宿主机内核 | 每台 VM 有自己的内核 |
| 启动与资源开销 | 通常较低，接近进程启动 | 通常较高，需要启动 Guest OS |
| 打包内容 | 应用、用户态依赖与运行配置 | 操作系统、驱动、应用与依赖 |
| OS 兼容性 | 镜像中的程序必须与运行平台的内核/架构兼容 | Guest OS 可与 Host OS 不同，由 Hypervisor 提供虚拟硬件 |
| 隔离边界 | 共享内核，配置不当会削弱隔离 | 独立内核，通常是更强的边界 |
| 典型用途 | 应用交付、开发环境、弹性服务 | 不同 OS、强边界、多租户基础设施 |

容器和虚拟机经常组合使用：云主机本身可能是 VM，VM 内再运行多个容器。macOS 和 Windows 上的 Docker Desktop 也通常先运行一个 Linux VM，再在其中启动 Linux 容器。

## 隔离边界

- namespaces 主要解决“看见什么”：进程树、网络接口、主机名、挂载点等可以具有独立视图。
- cgroups 主要解决“能用多少”：限制和统计 CPU、内存、进程数等资源。
- 镜像提供进程所需的用户态文件，但容器仍使用运行它的内核。
- `--privileged`、挂载 Docker socket、挂载宿主机根目录或授予过多 capabilities，都会显著削弱隔离。
- 能运行不等于安全隔离。对不可信代码或强多租户场景，应评估 VM、沙箱运行时或其他更强边界。

## 与相邻概念的区别

- **容器与进程**：容器至少包含一个进程，还包含文件系统、网络、资源限制和安全配置等运行上下文。
- **镜像与容器**：镜像是创建容器的只读模板；容器是依据镜像和运行参数创建的实例。
- **Docker 与容器**：Docker 管理容器，但容器生态并不只包含 Docker，OCI 规范也支持其他实现互操作。
- **隔离与虚拟化**：容器通常被称为操作系统级虚拟化，但它并不虚拟一套完整硬件和内核。

## 前提与适用范围

本页以 Linux 容器为主。Windows Containers 使用 Windows 内核机制，Hyper-V isolation 还会引入轻量 VM；学习 Docker 基础时应先明确自己正在运行 Linux 容器还是 Windows 容器。
